# Plan — Namespace schema CRUD

**Session:** 2026-09-25_22-16  
**Spec:** [docs/superpowers/specs/2026-09-25-namespace-schema-crud-design.md](./superpowers/specs/2026-09-25-namespace-schema-crud-design.md)  
**Approach:** A — dedicated `NamespaceChange` stack (not extending table `SchemaChange`)

## Summary

Add end-to-end PostgreSQL namespace management: create, rename, drop (RESTRICT default / CASCADE opt-in). Mirror the table structure editor’s preview → confirm → apply safety model. Surface actions on explorer schema folders; show empty schemas via `list_schemas`.

## Principles check

- **KISS:** One dialog for three actions; no owner/ACL/move-table  
- **YAGNI:** No schema comparison, no search_path UI, no dependency graph  
- **SRP:** `namespace_changes.rs` separate from `schema_changes.rs`  
- **DRY only where it helps:** reuse identifier quoting, operation gate, ChangeError shape

## Workstreams

1. **Rust core** — `namespace_changes` plan/apply + `list_schemas`  
2. **Tauri IPC** — register commands; TS API wrappers + types  
3. **UI** — explorer list/menu + namespace dialog  
4. **Refresh wiring** — tabs, diagram, completions  
5. **Docs + tests** — feature doc, Rust + frontend coverage

## Risks

- Naming collision with existing `SchemaChange` (mitigated by `Namespace*` names)  
- Accidental CASCADE (mitigated by default RESTRICT + checkbox + typed name)  
- Dropping `public` (warning only; same confirmation)

## Out of scope

Owner/ACL, move table between schemas, visual dependency preview.
